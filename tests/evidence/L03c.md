# L03c handoff

WhatsApp and print outputs are projections of the same source list, in the same order and words. The TEST text is 281 Unicode characters, including its final newline. G12 checks exact WhatsApp parity, print step parity, page address/check status, text at least 12pt, parsed PDF page count and extracted PDF text against the print HTML.

Decisions inherited from the card and earlier PRs:

- Fixtures contain one TEST fact and one TEST contact; real rules are unchanged and export only verified rows.
- Real test content stays draft and uses no fake registry references. The separate TEST site demonstrates the referenced fact/contact in every format.
- DRAFT: Satya approves all i18n labels, the privacy claim and the no-contact claim, including the new format labels.
- English opening is the approved house-rules line; Odia and Hindi remain empty and deferred.
- The free-licence British English dictionary, source helper text rules, verified-only export and primary-domain policy are retained from L03b.
- Source hashes remain proposals for Satya; protected registries are never edited.
- security.txt uses the card's URL. Satya must switch on private vulnerability reporting and approve the expiry. Branch protection also remains Satya's task.

New implementation decisions:

- Hugo output formats are selected explicitly with outputs in draft front matter. Templates read the exported canonical projection.
- Short formats select a non-empty prefix of the first list. Single-line plain prose and fact/contact references are supported; unsupported Markdown or multiline continuations fail instead of silently dropping words.
- Draft formats say Draft awaiting review. No page verifier or verification date is invented; signed pages will use their human-set date.
- The WhatsApp share link is suppressed while C18 is pending. Its future implementation requires a verified url-base contact and exact encoded canonical text. Satya must verify C18 before a real share link can appear.
- WeasyPrint 66.0 runs only in the L03c Actions formats job. Python gate code uses only the standard library and invokes Poppler CLI tools for real PDF parsing.
- Print sheets contain the first steps, the opening, the page address and the trust frame; no QR code. The print HTML uses black text on white, base 12pt and larger title/address text.
- G12's PDF text comparison ignores layout whitespace and at most one generated list label per expected step. All other visible characters must match the print HTML. The first CI run proved the original comparison incorrectly counted the generated list label as extra text; a failing regression test preceded this fix.
- No merge, deploy, secrets, account changes or real verification flags are part of this work.
- The final adversary pass added G1 checks for plain email addresses and URLs without a scheme; they cannot be mistaken for local paths. Their tests failed before the fix.
- CI uses its preinstalled Chrome for closed/expanded phone-width captures and a raw network log. Screenshot dimensions are checked, and any recorded request to an outside host fails the capture job. This resolves the absent local browser without installing one on the PC.

Control evidence: length, page limit, WhatsApp parity, print parity, font minimum and PDF text parity each have a disabled-control mutation. Real artefacts in CI are mutated to overlong WhatsApp text, a WeasyPrint two-page PDF and a step absent from the source, then restored from backups and checked GREEN.

Local verification excludes PDF authoring, as the card requires. CI evidence and visual review will be recorded after the run; until then, the PDF page count and browser screenshots are NOT CHECKED.

Human checks still required: Claude review, Satya's i18n/legal text decisions, real fact/contact verification, signature/AI footer wording and Satya's merge. This handoff supplies evidence, not approval.
