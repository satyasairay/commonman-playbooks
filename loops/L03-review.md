## Blockers (gates, PR #3)

- **B1. G1 and G11 step-number exemption.** `gates.py:165` strips any number at the start of a line followed by `.` or `)`. `1930. Call this number first if money left your account.` builds as `<ol start="1930">`, the reader sees "1930.", and every gate is GREEN. Same for `155260) ...` and any number up to 9 digits. Fix: exempt only lists numbered 1, 2, 3 in order; fail G1/G11 on any built `<ol start>` other than 1.
- **B2. G11 misses number words, time words and legal names** (`gates.py:23-24`). All GREEN: "within a few days", "in a week", "for a year", "golden hour", "in a fortnight", "fifty days", "zero liability", "fifty per cent", "fifty rupees", "half of the money", "before the end of March", "on the same day", "Code of Criminal Procedure", "Integrated Ombudsman Scheme", "Master Direction", "RBI circulars", "An RBI rule", "SEBI Regulations", "Both Acts", "the Sections". Caught correctly: "within three working days", "in 5 days", "90-day", "₹25,000", "Rs. 5000", "section 173", "Limitation Act". Fix: complete the number words (zero, forty to ninety, half, dozen, few, several, couple), time units after any quantifier (including fortnight), month names, "per cent"/"percent", and legal nouns in singular and plural (Act, rule, circular, section, Code, Scheme, Direction, Regulation, Sanhita, Adhiniyam, Ordinance, notification).

## Should-fix: gates and CI (PR #3)

- **S1. G10 sentence length** (`english.py:81`): sentences split at every newline, so a 34-word sentence hard-wrapped over two source lines is GREEN. Join lines inside a block before splitting.
- **S2. G10 Hinglish** (`english.py:66-67`): multi-word allowed names are split into single words, so "didi", "saathi", "nyaya" pass; the en_GB list also has "beta", "bas", "na". Match allowed names as whole phrases; add a Hinglish deny list checked before the dictionary.
- **S3. G1 web addresses** (`gates.py:21`): only in/com/org/net/gov/nic/io/invalid endings. "bank-refund.online", "kyc-update.top", "bank-help.app" and "help [at] bank [dot] co" are GREEN. Scam cards will quote exactly these. Accept any alphabetic ending of 2+ letters; detect "[at]" and "(at)".
- **S4. G7** (`gates.py:25`, `:168`): matches only exact, case-sensitive `[[VERIFY`, and HTML comments are stripped before G7, so `[[ VERIFY`, `[[verify`, `[VERIFY` and a marker inside `<!-- -->` ship. Internal file names such as "facts.md" are not caught. Search the raw source, comments included, for `\[+\s*verify` without case; add `*.md` names.
- **S5. G8** (`gates.py:257`): runs only when `kind` is exactly "playbook" or "card". A page under playbooks/ with no kind, `kind = 'Playbook'` or `kind = 'scam-card'` builds with no opening line and passes. Fail on a missing or unknown kind under playbooks/ and cards/.
- **S6. Non-.md content** (`gates.py:317`, also formats.py, format_gate.py): a live page saved as `.markdown` with no signature passes G2, G3 and G8. Fail on any content file that is not `.md`.
- **S7. G9 kind matching** (`gates.py:89`): `kind: Rule` or "deadline (RBI circular)" with a news source is GREEN. Reject any kind outside the closed list in registry.py. (Look-alike domains are all caught correctly.)
- **S8. Exemptions too wide.** The evidence blockquote (`gates.py:280`) skips G7 and the Devanagari/Odia script ban, not only G10. The trust-frame lines (`gates.py:283-285`) skip every check, including G1, and `verified_by` is never checked: `verified_by = 'Satyasai Ray. Paisa gone? Call 1930 ... [[VERIFY'` renders and passes. Keep G1, G7 and the script ban on quotes; check `verified_by`.
- **S9. G4 can be bypassed** (`gates.py:210-211`, `:226`, `:248`): `<style>` content is never checked, and only src/srcset/poster/data/link href are. `@import url(https://...)`, `@font-face{src:url(https://...)}`, `<a ping>`, `<body background>` and `<svg><image xlink:href>` are all GREEN. The browser network check runs only on the TEST index page. Scan `<style>` for `url(`, `@import`, `@font-face`; treat any absolute URL in any attribute other than a registry `href` as G4; run the network check on print.html and every built page.
- **S10. Gates run only on the drafts build, into `public/`** (`verify.py:38`). G3's /method/ and /corrections/ are drafts, so only a drafts build can pass; Hugo does not clean `public/`; CI uploads it as `public/`. RUNBOOK R2 followed literally would rsync drafts (including the TEST page) live, and R1's takedown ("set draft: true") would not work. Build previews into `.cache/preview-public`; make production `hugo --cleanDestinationDir` with no `-D`; gate the production build; add a gate that fails if any draft has output there.
- **S11. G3 commit id** (`gates.py:267-269`, `baseof.html:14`): with BUILD_COMMIT unset, `data-build-commit=""` and "Build  · " pass. Require a hex SHA and a valid date.
- **S12. Mutation evidence is whole-gate only.** `mutations.py` proves that removing all of a gate's errors turns tests red. Breaking one control at a time, the 34 tests stay GREEN for: G9 https/username check, G2 live-page signature, G2 recheck boundary (`<=` to `<`), G2 card confidence label, G3 required pages and security.txt, G3 live page missing from build, G7 loop-id and internal-path patterns, G1 "call NNNN", G12 share-link parity, G12 print address and check status. Add one failing test per control.
- **S13. Mutation harness edits tracked files in place** (`mutations.py:69-99`, `format_mutations.py:119-148`), restoring only in `finally`. A crash leaves a disabled control (for example `export.py` with `if True`, exporting unverified rows) that could be committed. Mutate copies in a temp folder, or end verify.py with `git diff --exit-code -- scripts/`.
